    结论

    当前最需要补上的，是地图整体的视觉组织：主要形体、材料之间的区别、受光区域的层次，以及战斗区域与装饰区域的主次。继续平均添加倒角、破损、灯和反射，收益会越来越小。

    我们的上漆玩具目标本身成立，没必要改成守望先锋的复制品。可以保留明快纯色、简洁角色和短回合玩法，同时学习它如何让一组简化建筑具有真实的结构、重量和生活用途。

    推荐顺序：构图与删减 → 建筑和道具的中等尺度形体 → 分区材质与光照 → 接触关系 → 局部装饰 → 特效。

    一、守望先锋值得学的具体内容

    1. 先有可玩的空间，再用美术解释这个空间

    暴雪介绍的流程从经过测试的灰盒开始，再由环境美术转化为建筑与道具。Midtown 制作者也明确描述了从灰盒、概念设计到建筑、道具、布景和灯光的协作。暴雪环境状态说明、Midtown 制作者资料

    对我们的含义：掩体首先是战斗约束，但最终应能读成售票亭、花池、工作台或设备机壳。地图编辑不能只把相同体块换成不同颜色，再散放一些主题小物件。

    2. 细节并不少，但细节服从更大的形体

    从本轮查看的 Midtown 街角看，砖缝、消防梯、店招和灯串很丰富，但桥体的大阴影、街角楼体、店面底层和天空开口先建立空间。Dorado 的庭院先通过拱廊、主入口、庭院中心形成结构，再用植物与暖灯补充。Suravasa 也并非“干净得没有纹理”，石材、植被和墙面变化都很多。

    这是对作品图的视觉分析，并非暴雪公布的统一比例规则。Midtown、Dorado、Suravasa

    对我们的含义：不能把“减少细节”等同于把墙面全部涂平，也不能把“增加细节”等同于全图加铆钉。需要的是主次，而不是统一的细节密度。

    3. 地图美术也要做减法

    暴雪的 Flashpoint 重做说明列出了降低部分遮挡、突出入口、减少杂物和强化区域主题等措施。美术编辑的价值包含让玩家更容易理解空间。官方重做说明

    我们可以先减少非交互的视觉噪声；改变掩体、道路或可穿越结构属于关卡调整，需要单独验证，不能冒充纯美术修改。

    4. 光照效果可以大量预计算

    暴雪公开描述了静态表面的方向性光照数据、AO 与移动物体使用的空间采样。其环境状态系统还允许组合光照变化。官方技术说明

    对我们的含义：优先研究可控的静态间接光和接触关系，动态灯留给角色与状态变化。不能把“实时效果多”当成接近目标的必要条件，也不应把当前顶点 AO 称为同等完整的光照方案。

    二、当前画面的八个主要差异

    维度当前样本里的表现地图编辑时应该改什么优先级
    视觉主次多张图的横梁、栏杆、地砖、屏风和边框同时清楚；背景也在竞争为出生点、转角、主交战区各定义一个视觉中心，清理其周边非交互线条P0
    建筑体积大平面加边框很多，突出边沿比凹入空间更显眼屋檐、门廊、窗洞、墙裙形成不同深度；外壳改造服从现有碰撞边界P0
    尺度节奏多数柱、栏杆、设备按相近粗细和等间距重复建立主梁／次梁、主体／附件、近景／远景的层级；优先改已有组件P0
    色彩分工多个物件都使用完整的高饱和颜色，部分图又被暖光统一染色保留主色，降低次要区域的对比；用明度与冷暖分区，不全局去饱和P0
    光照结构浅色大面容易平亮；阴影常像统一色块；局部灯池有但衔接弱设计大面积明暗关系，再补门洞、檐底、设备底部和地面接触P1
    材料身份石材、喷漆、塑料和金属常接近同一套平滑涂层先区分高光宽度、粗糙度和结构，再按位置添加有限纹理P1
    使用痕迹通用崩角、斜缝、补丁容易到处出现只在脚踢、搬运、漏水、摩擦等有原因的位置做旧P1
    环境叙事主题容易依赖少数标志物，空地和墙面缺少用途关系每一区域安排一个可读的作业／生活组合，避免平均摆杂物P2

    A. 构图：从“把物件放满”转向“给交战区留出安静背景”

    办公室天花管线、屏幕文字、工位边框与角色同时抢眼；温室入口后面多层白骨架叠成线网；雨市顶棚和摊位也有强重复节奏。这些结构单看都合理，叠在同一视角会降低重点的辨识度。

    编辑动作：先标记常见敌人出现的屏幕区域；在这些区域后方保留较完整的墙面、幕布、植物暗面或设备侧面。通过合并相邻同类视觉块、减弱无用途的接缝、降低后排非交互装饰对比来实现。不要删除必要掩体，也不要给敌人背后永久画一个随镜头的亮斑。

    不要把所有常用入口都画成同样的高亮框。主入口、侧路、不可通行装饰门必须有不同的信息层级；当前爆炸桶等玩法标记应保持跨图一致。

    B. 形体：我们缺的主要是中等尺度结构

    宏观上能识别“货场／温室／城堡”；微观上已有倒角、缝和做旧。中间一层仍有空缺：檐口如何支撑、机壳如何包住内部、窗户如何坐入墙体、植物如何组成一簇。

    编辑动作：一次只改一组占画面面积大的组件。例如沙门的门洞—墙裙—棚布，温室的主拱肋—次肋—节点，渡轮的舱壁—舷窗—灯罩。让前后错层和遮蔽本身产生明暗，而不是增加线条模拟深度。

    toy_kit.py 已有通用微锥体、压顶、窗口和棚布；导出器会按厚度与最短边选择单段倒角。它是生产工具，不是所有材质的最终造型规范。金属薄板应折边，石材应厚重斜切，塑料外壳可有更连续的曲面，植物应有弯曲脊线。不能把所有构件一起加粗或一起加倒角段数。

    C. 光：减少泛白只是第一步

    刚完成的堆货场降光使颜色关系更稳定，但无法单独补出墙脚、檐底和空间间接光。单纯继续压低太阳与环境光，会让整个场景变暗，却仍然平。

    当前顶点烘焙有两类：室外天空遮蔽与颜色渗透，室内短距离 AO；结果乘入 albedo。它能改善接触，但会连同受直射光的底色一起压暗，与独立的间接照明不是同一件事。重复放置的同一 kit 还会被排除为烘焙接收对象，避免把某个位置的结果用在全部实例上；不能假定每个重复件都有独立接触烘焙。

    建议保留顶点 AO 的轻量优势，先在一张样板图试验：用少量分区的间接光数据或 LightmapGI 表现稳定建筑；用已有局部灯服务移动敌人；让普通与狂暴状态只覆盖明确的光源和氛围。烘焙静态结构，不烘焙会开门、移动或破坏的遮挡。是否迁移 LightmapGI 要检查 UV2、资源体积、动态物体采样以及两种模式是否能共用，尚未验证。

    蓝天、温室白骨架和办公室紫墙是保留项。光照应改变表面的受光关系，不能再次把这些色彩洗灰。暖光冷影可以用于部分地图，不是所有地图、所有材质都必须套的滤镜。

    D. 材质：需要的是材料之间的区别

    当前 map_lookdev.gd 按材质资源名分类，并给多类材质赋粗糙度、金属度。它比全图一材质好，但“同名都套同一反应”仍比较粗。彩漆金属外壳和裸露金属边缘也应区别处理；不能为了反光把整块彩漆提高金属度。

    建议每图先把三个高频材料做清楚，例如货场的涂漆波纹板、粗混凝土、裸露滚轮／叉齿。几何负责轮廓、孔口与真实厚度；小尺度法线／粗糙度图负责不影响轮廓的细节。可尝试共用边框纹理条带（trim sheet）与小图集，替代远处密集几何缝和铆钉，但不预先承诺一定更快。

    现有材质刻意压低了随机颜色噪声，这是应保留的方向。补回纹理时优先增加有方向和用途的变化：轮胎经过的摩擦、雨棚下干燥区域、金属折边高光、墙脚局部积尘。不要用整面灰色噪声制造“真实感”。

    E. 反射与雾：作为局部强调

    雨市已经有很强的湿地身份；当前第一视角中的反光碎块也较密。下一步应调整干湿分布，让通行面和灯下反光形成更大的可读区域，而不是继续增加全地面反射强度。

    办公室、车站的干燥地面要以弱、宽高光表现，橡胶传送带保持哑光；沙门与雪地不应该迁移成雨市。雾优先用远景距离雾组织深度，室内光束只放在有来源的位置；透明光束是近似表现，不应在文档中称为真实体积光。

    F. 描边：先解决背景，再减线

    当前深度描边已经去掉颜色差检测，且有近远淡出。仍能在细杆、窗框、货柜波纹等结构看到不少细线；单纯降低描边不能消除几何本身带来的密集边缘。

    先简化非交互后景的线条，再在同机位比较环境描边开关。保留玩家必需的掩体边缘辨识。角色轮廓光也不能替代背景整理：摄影棚和雨市的暗色敌人仍容易主要靠亮边辨认，身体的体积信息比日间弱。

    四、性能与实现边界

    我们的 Web 与原生目前均用 Compatibility。Godot 4.7 官方表列出：支持色调映射、调色、Glow、SSAO、ReflectionProbe 和已烘焙 LightmapGI 的显示；不支持引擎的 SSR、体积雾、SSIL、SDFGI，也没有原生 Decal 功能。不能套用早期版本“Compatibility 没有 Glow／SSAO”的结论。Godot 4.7 渲染器比较

    这张能力表不证明项目里每个参数的视觉收益，也不证明手机开销可接受。实际启用效果要做开关对照和 Web 检查。地面贴花可采用受控网格或现有 shader 的投射遮罩；透明层多时仍可能增加开销。

    手段可能的收益需要支付与验证的成本
    重排／减少非交互装饰大色块更清楚，可能减少绘制验证不能丢失方向信息与玩法线索
    重点物件重新建模剪影、结合阴影、材质厚度更可信局部面数；必须统计烘焙细分之后的规模
    小图集、法线、粗糙度、trim sheet减少不影响轮廓的小几何，材料更明确下载、采样与显存；可能增加材质批次
    顶点 AO / 选区静态光照低运行时成本的接触与间接光烘焙时间、顶点／光照图体积、模式切换一致性
    静态环境反射金属与玻璃身份更明确探针内存、分区与错误反射；移动物体倒影不精确
    动态灯、反射视口、透明光束动态气氛绘制次数、重叠与切换长帧；本轮不优先扩张

    不能承诺“删掉小件就一定更快”或“换贴图必然降开销”。旧记录包含不同设备、版本与负载，不用于本轮计算提升百分比。

    五、建议如何开始下一轮

    样板选择：沙门一个街角，随后办公室一条过道

    沙门已有稳定色彩、厚窗与棚布，适合检验中尺度结构、门洞阴影和材质；办公室用于检验室内视觉降噪、光区组织和角色背景。雨市保留为已有效的风格标杆，优先做控制密度的局部修整。不是再给 12 图同时套一套参数。

    • 编辑简报：每个样板一句主题、一个主要地标、三个保留色、三个关键观察点；标出必须保留的通路、掩体高度、射线和机关。
    • 只做摆放与减法：不加灯、不换材质。沙门围绕主门楼整理视觉节奏；办公室先减少天花和后排无意义的重复线条。保留一张原版随时切换。
    • 只改主形体和结合关系：重做一组高频组件。正常战斗距离下必须能指出变化，而不是放大找细缝。
    • 锁定色板，分区打光：调整主光方向、环境补光、檐底接触和局部落光；保留被认可的蓝天与纯色。做普通、狂暴和重开检查。
    • 最后补材料和使用痕迹：让近处有合理细节，远处保持形体。只有某个区域确实需要时才加反射或光束。
    • 复核并扩展：相同机位、FOV、曝光；全彩、灰度、缩略图三种检查，再做带敌人的移动观察。至少覆盖逆光、阴影、亮墙和复杂背景；截图滤镜只用于分析，不算实际游戏改造。

    完成条件

    • 在 640×360 的缩略图里仍能辨认入口、主要活动区和地标；这是一项检查方法，不是声称已通过的测试。
    • 在游戏常见射程、包括 15–25 米的远端情况中，角色头肩与背景能分开；不能只靠强边缘光。先在固定目标上比较，再由人实际游玩确认。
    • 角色经过门洞、灯池和阴影时，材料颜色和受光变化连续；白墙有层次、阴影不死黑。
    • 通道、射击、掩体、破坏和重开维持原行为；视觉洞口与碰撞一致，无悬空支撑。
    • 相同设备、分辨率、路线下测普通与狂暴切换的 P50/P95/P99、长帧、draw calls、几何量和显存。目标沿用项目 60 FPS，不能用静态截图代替性能证据。

    六、代码定位

    • scripts/maps/toy_palette.gd：地图主光、环境补光、雾与角色轮廓色。
    • scripts/maps/toy_look.gd:5：全图共享曝光、饱和度与对比度。下一轮优先做地图区域关系，不先继续改这里。
    • scripts/maps/map_lookdev.gd:113：按原材质转换、按名称分类的入口。
    • assets/shaders/toy_paint.gdshader、map_surface.gdshader：原色、顶点颜色、微弱表面变化与高光。
    • assets/shaders/comic_outline.gdshader：深度边缘与距离淡出。
    • tools/maps/toy_kit.py:543：按尺寸选择单段倒角的导出器；各地图专属母版应决定最终造型。
    • tools/maps/bake_vertex_light.py:1：顶点光的适用边界；:100 附近的实例处理；不要误认为是完整方向性 LightmapGI。

# 移动 Safari 音频恢复

- 移动 Safari 用独立的 Web Audio 路径播放玩家枪声。普通、恶搞和蟑螂模式复用原有单声道样本，在浏览器中各解码一次；每次开火用当前音频时钟立即播放，不复制采样数据。最多同时保留四个声音，并合并同一帧补算造成的过密触发。不改变开火、弹匣和计分规则。
- 切后台或失焦时清理短音效；手动暂停只清理枪声，不切断正在播放的战斗警示。返回前台时尝试恢复音频；真实的继续或重试点击可再次解锁。浏览器不能建立直接播放时保留原有 Godot 路径；一旦直接播放已启用，中断期间的枪声丢弃，不转入可能同样挂起的 Godot 队列。移动 Safari 下只限制装饰物破碎声的并发和距离，保留敌人、命中、飞掠和爆炸等战斗提示。
- 音乐每 0.5 秒对照游戏时间，连续三次同方向偏差达到 250 毫秒才淡出、重定位并淡入。两次校正至少间隔 5 秒，切曲后改用本段音乐的起点。暂停、结算、静音和非循环曲尾不会触发校正；音频时钟不影响比赛倒计时。

## 验证与实机复测

- `node tests/web_audio_test.mjs`：验证缓存复用、短音效清理、手势解锁、中断期间不重放和降级。
- `godot --headless --path . --script tests/web_music_sync_check.gd`：验证持续偏差、淡入淡出、暂停取消、冷却和循环曲边界。`tests/arena_music_check.gd` 验证九张地图的曲目与阶段切换。
- `node tools/browser/check_web_audio.cjs <web-url>`：在正常 Web 导出中完成渡轮的一局，使用真实 Chrome AudioContext、触控输入和 CPU 限速，分别注入音乐中断及两次页面前后台事件，再通过结算重试验证新一局的时钟和枪声。这不是 iPhone Safari，也不测量扬声器的物理延迟。
- iPhone 上建议用内置扬声器在 Safari 中打完一局，停在结算界面切后台几秒，返回点重试并立刻连续开火；重复数次，再在设备自然发热时重试。比较枪口反馈和声音是否长期错位。如需比较，可在同一入口加 `?audio=legacy` 对照旧路径。`?perf=1` 的本地帧报告包含音频状态、触发及降级计数与音乐校正次数，不会上传；浏览器延迟字段不是物理出声时间。

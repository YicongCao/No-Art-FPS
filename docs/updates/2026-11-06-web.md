# No-Art-FPS Web 导出

日期：2026-11-06。

新增 Godot 4.7.2 单线程 Web 发布配置，使用既有 Compatibility 渲染。构建命令为 `./tools/export_web.sh`，输出到 Git 忽略的 `builds/web/`；`tools/verify_web.py` 校验必要文件、WASM 文件头、无 PWA／跨源隔离要求，以及 PCK 目录中不存在参考录像、源美术、设计文档、截图或测试资源。每次导出生成包含字节数与 SHA-256 的清单。

HTML 加载页在引擎脚本下载前显示。进度来自 Godot 的真实下载字节数；无法计算总量时显示不定进度。文件下载完成与世界可交互分开表示，真正的首帧渲染就绪后才揭开标题。加载失败有重试入口。页面说明桌面键鼠控制，触摸设备明确提示当前没有触屏操作。

Web 中 FIRE、重试和恢复按钮的输入回调直接申请鼠标捕获，避免异步转场结束后申请被浏览器拒绝；丢失捕获时暂停计时。恢复时用独立 CAPTURING 状态等待浏览器异步结果，等待期间计时、角色与敌人停住；750 毫秒仍未成功则回到暂停菜单，不能绕过浏览器的输入手势要求。敌人模型使用已被开场画面预热的资源缓存，运行时导航改为同步烘焙，保留原生异步路径。

发布包附带 Rajdhani 字体许可证和 Godot 4.7.2 的 MIT／第三方版权清单。后两者取自官方 `4.7.2-stable` 标签的 `LICENSE.txt` 与 `COPYRIGHT.txt`，保存在 `web/` 以便离线重复构建。

运行规则测试已通过：空闲、重复死亡、倒计时边界、结束后计分拒绝、重开、固定 tick 时钟。原生 headless 启动运行 180 帧后退出码 0。导出成功且 116 项 PCK 资源目录范围检查通过；最终包包含 10 个运行／许可文件及 SHA-256 清单，原始文件合计约 51.23 MB。

本地 Chrome 检查确认 HTML 加载、实际标题首屏、FIRE 点击及装弹转场可用。受控 Chrome 文档申请 Pointer Lock 返回 `WrongDocumentError`，因此当前不能据此确认浏览器中的完整一局及鼠标瞄准；这个错误表示浏览器未接受该文档的捕获申请，不通过降低手势保护来绕过。检查也发现恢复时立即检测捕获的竞态，已改为上述 CAPTURING 状态。仍需在可获取鼠标锁的前台桌面浏览器验证瞄准、移动、暂停恢复及完整一轮重开。线上资源及浏览器检查另行补充，不以编译成功代替试玩。

依据：[Godot Web 导出](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)、[自定义 HTML Shell](https://docs.godotengine.org/en/stable/tutorials/platform/web/customizing_html5_shell.html)。

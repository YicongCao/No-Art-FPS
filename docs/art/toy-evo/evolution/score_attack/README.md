# 货场工业样板

2026-11-12，toy 分支；基线 `912a276`。本阶段模型、实机对照、功能回归及性能复测已完成。

[实机前后对照](comparison.html)：正常战斗距离、近景、侧面和箱门四个固定机位；1440 × 810，FOV 63°。此次没有调整光照、色板、材质参数或顶点烘焙，画面差异来自模型与网格组织。

## 实现

- 叉车：连续收放的车壳与配重外壳、独立圆弧轮拱、略收分的护顶架、圆角顶盖、座椅、方向盘和液压门架。保留原有黄车身、蓝色轮胎及支架、浅色门架，叉齿位置与车身占地沿用原布局。
- 集装箱端门：外框、折边、封闭凹入面板和压制板形成层次；可开门与固定集装箱四种色款都更新。没有增加单独的纹理资源。
- 可开箱体按同材质、同铰链父节点合并。壳体和两扇门保持独立，不能跨门扇合并。表面节点由73个降到9个；叉车仍为4个。相同模型实例共享网格，颜色覆写仍按箱体分别保留。
- `tools/maps/apply_yard_hero_models.gd` 只替换视觉子节点，更新13个资产根节点；保留作者场景中的所有非网格节点，避免重新生成整张地图导致碰撞或导航变化。源模型位于 `art_source/no_art_kit.blend` 和 `art_source/playbox_props.blend`。

## 性能与长帧复核

Apple M5，Godot 4.7.2 Compatibility，1280 × 720窗口，VSync开启。每种状态前后各三轮；每轮采样8秒，60帧预热，采样时不截图、不并发建模/烘焙。自然切换让实际对局运行到第42秒才开始记录，保持敌人AI运行，跨过第45秒。表内分位数为三轮中位数；[原始数据](data/performance.json)保留每轮最大值和长帧计数。

|状态|P50 毫秒 前→后|P95 毫秒 前→后|P99 毫秒 前→后|draw calls P50 前→后|超过33.33毫秒帧占比 前→后|
|---|---:|---:|---:|---:|---:|
|普通|37.01 → 36.25|48.50 → 45.52|58.01 → 48.68|2328 → 1477|72.8% → 67.4%|
|狂暴稳态|40.70 → 35.76|59.67 → 49.41|68.62 → 54.94|2423 → 1614|85.3% → 65.5%|
|合成跳时钟|40.84 → 37.24|58.55 → 52.19|74.52 → 65.77|2432 → 1570|85.8% → 74.0%|

三轮自然切换中，新场景最大帧为55.25–67.44毫秒，均没有超过100毫秒；旧场景为61.47–106.68毫秒。自然切换的P95中位数仍上浮约2.88毫秒，不能宣称每项指标都改善。

普通状态的 draw calls 中位数下降约36.6%，可见图元中位数从308,684增加到329,256。常态帧间隔改善远小于绘制批次的下降幅度；不能把减少批次直接等同于同百分比的FPS提升。这台机器上前后都超过60fps预算，本轮没有证明全图60fps达标。

### 为什么补测自然切换

原始的合成采样在启动后直接把时钟跳到第45秒，混合了模式切换、补兵与敌人状态变化。第一轮新场景出现437毫秒最大帧；旧/新场景交替补测三次，新场景仍有345–460毫秒尖峰，旧场景为59–77毫秒，不能忽略。

进一步记录发现切换函数同步耗时不到0.3毫秒。冻结局内与敌人物理逻辑后，新场景的纯切光检查最大帧约56毫秒；这仅说明额外工作依赖运行状态，尚未完全隔离底层原因。随后改用自然第45秒切换，补足前后各三轮，结果另列，不用自然测试覆盖或替换原异常数据。合成跳时钟路径的尖峰仍未消除，不能宣称已经修复全部卡顿。见 [诊断数据](data/transition-diagnostics.json) 与 [冻结逻辑的测试脚本](data/frozen-transition.gd.txt)。

帧间隔包含CPU/GPU调度与VSync，不是纯GPU计时；固定起点、缓慢转头的样本也不代表全图移动或集中爆破时的最坏开销。破坏玩法已通过功能回归，主动爆破的性能尚未单独采样。

## 复现

```sh
blender --background --python-exit-code 1 --python tools/build_assets.py
blender --background --python-exit-code 1 --python tools/build_playbox_assets.py
godot --headless --path . --editor --import
godot --headless --path . --script tools/maps/apply_yard_hero_models.gd
godot --path . --script tools/maps/capture_scene_evolution.gd -- score_attack after
python3 tools/qa_run.py -- --qa --containers
python3 tools/qa_run.py -- --qa --routes
python3 tools/qa_run.py -- --qa --destroy
python3 tools/maps/measure_scene_evolution.py score_attack after
python3 tools/maps/measure_scene_evolution.py score_attack after --phases natural-transition
```

资产生成器也会导出原有武器等资源；本阶段将无关GLB恢复原样，只提交上述六个模型。场景更新工具按根节点与材质名匹配，保留原材质，并检查每个导出部件为单材质；不依赖会随建模顺序变化的 `Cube.001` 等网格名称。

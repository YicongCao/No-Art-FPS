# 沙门街角样板

2026-11-12，toy 分支。基线为 `b757d92`，当前状态：本阶段已完成模型、烘焙、实机回归及性能复测。

[同机位对照页](comparison.html)提供最终实机与仅几何两种对照。四个机位覆盖正常战斗距离、近景、沿街侧向和长门；1440 × 810，FOV 63°。未修改天空、太阳、环境参数、材质色板或曝光。

## 改了什么

- A Long 第一栋临街房屋：墙带深度由0.36米增至0.64米，窗洞从1.18 × 1.33米放大至1.46 × 1.68米；蓝色百叶窗退入墙内，斜切窗侧壁连接外墙与内框，窗台和过梁形成真实纵深。窗后保留实心背板，表达封闭窗的碰撞语义。
- 两个近景摊位：原来逐段厚盒拼成的棚改成连续曲面壳体；色带只分材质，不再为每段添加内部端面。圆弧垂边、独立曲线侧肋与斜撑形成清楚轮廓。棚脚落到地面，横向占地及最低垂边高度保持。
- 长门：统一石色的内圈、外层台阶拱圈及收分扶壁。拱圈内径、门净宽和净高未改。

此次是一个街角样板，不声称重建了沙门所有建筑。新增几何原语在 `tools/maps/hero_geometry.py` 中按需调用，未全局替换旧 kit。生成器保留单独可编辑的 Blender 对象；游戏输出仍按原区域、材质合并。

所有状态的帧间隔都已在改造前超过60fps预算，且前后均有超过200毫秒的偶发长帧。切换测试直接把局内时钟跳到狂暴起点，同时触发人口/AI状态变化，不能用于隔离某一个视觉效果的开销。这里只说明这次模型改造在受控起点负载下的成本；没有证明整张地图60fps达标，也没有修复既有切换卡顿。帧间隔包含CPU、GPU调度和VSync，不是纯GPU计时。

## 复现

```sh
blender --background --python-exit-code 1 --python tools/build_sandgate.py
godot --headless --path . --editor --import
godot --path . --script tools/maps/capture_scene_evolution.gd -- sandgate after-geometry
blender --background --python-exit-code 1 --python tools/maps/bake_vertex_light.py -- sandgate
godot --headless --path . --editor --import
godot --path . --script tools/maps/capture_scene_evolution.gd -- sandgate after
godot --path . --script tests/sandgate_check.gd
python3 tools/maps/inspect_model_budget.py assets/models/sandgate
```

全套生成器会写出所有区域；本阶段提交前将改动范围以外的导出恢复为基线。性能脚本为 `tools/maps/capture_visual_performance.gd`，通过 `PERF_MAPS=sandgate`、`PERF_SECONDS=8`、`PERF_FRENZY=1` 或 `PERF_TRANSITION=1` 选择负载，每种运行三次。普通运行将后两项设为0。

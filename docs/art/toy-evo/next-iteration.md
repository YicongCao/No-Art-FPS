# 场景模型下一轮进化方案

2026-11-12，toy 分支。本文保留设计时的判断；用户已授权分阶段完成全图，实施状态见 [进度记录](evolution/README.md)。

依据：本目录 README、五件套概念图、归档实机图，以及当前 `tools/maps/toy_kit.py`、`tools/maps/bake_vertex_light.py`、办公室等地图构建器。归档图用于判断现有方向，不冒充本轮重新渲染或性能复测；未逐件检查全部地图的每个模型。

## 结论

现有五项原则已完成一轮全图落地，下一轮的重点应从“给现有方块增加建筑细节”转向“设计物体本身的轮廓、体积和组合关系”。共用代码负责高质量生成，专属母版负责每张地图的性格。

同样的底座、边框、分缝越铺越多，画面可能更复杂，却依然像旧地图。敌人模型迭代已暴露这个问题：配件变化不能替代主形体变化。场景应先让出生后第一屏和常走路线看得出变化，再扩大覆盖。

## 当前基础与实际差距

1. 工程基础已经具备：视觉模型与布局碰撞分离，共用导出器支持倒角与法线，静态环境可烘焙顶点光。这些应继续复用。
2. `toy_kit.py` 的主要组合原语仍是微锥盒、压顶、窗框和条带雨棚。它们改善了边缘，但不足以生成鼓起的机罩、收分的塔楼、拱肋与有张力的棚布等物体主形体。
3. `recessed_window()` 的代码明确把阴影背板放在宿主墙体前方，再让窗框前凸。这是有效的层叠假凹陷，但不是从墙体中形成真实窗洞；不能把现有实现描述成已经具有完整墙厚。
4. `cambered_canopy()` 用三个截面表达弧度，每条色带再分成独立厚盒。下一轮可以共用连续棚面几何、用材质分条，避免不必要的内部接触面；边缘仍需真实厚度。
5. 导出器统一使用单段倒角，适合普通建筑的大部分边，却不适合所有近景物体：塑料外壳需要连续曲面，石材适合较宽斜切，钣金需要折边。全部加倒角段数也不能解决物体设计问题。
6. 归档办公室截图已有很多天花管线、立柱与工位横线，继续平均加细节可能分散敌人轮廓。温室白骨架和雨市冷暖反射则已有明确身份，应围绕这些特征深化。

## 六个进化方向

### 1. 先改主轮廓，再做表面

优先修改玩家能从剪影认出的部位：叉车车身与护顶架、渡轮舱体与船舷、天文台圆顶与开口、旋转木马顶棚、温室主拱肋。形体用多截面收放、轮廓挤出和曲面壳体生成。

不是每个墙角都要变圆：建筑保持稳定平面，转折处按石材、金属、塑料分别处理；机械和家具通过主体收放获得体积。已经成立的地标比例保留，只改过于简化的局部轮廓。

### 2. 做有深度的结合关系

优先制作真实壁厚、凹入面、包围关系和支撑结构：墙面围绕窗洞生成，窗框坐进墙厚；机柜用外壳包住内胆；雨棚有独立骨架与连续外壳；玻璃卡入框槽。

实心封闭窗保留玻璃或背板，不能做出“明显可射穿但子弹被整墙挡住”的假孔。通行门宽、掩体顶面与子弹碰撞边界是约束，不以“视觉与碰撞分离”为理由忽略它们。外凸装饰应优先朝非通行面或向内部安排。

### 3. 放大有用的特征，删减低收益细节

按屏幕占比和接近频率决定投入。近处柜门握把、框口厚度、鱼池压边值得建；远景几厘米螺栓和等距小拼缝可以省略。

作为尺度示例：垂直视角70度、画面高900像素时，2.6厘米的细节在15米处仅约1.1像素。这不是当前游戏视角的测量值，而是说明为什么“参数已经加了细缝”不等于玩家看得见。判断时也要考虑轮廓和高光，不能只按像素阈值机械删除。

同一画面建议分三层：少量高辨识重点物件、支撑空间的建筑模块、大面积安静背景。比例以实际构图为准，不给每张地图机械套固定百分比。

### 4. 为每种材料设计自己的形体语言

- 彩漆塑料：较大的圆角、连续外壳、少量清楚的分件线。
- 石材灰泥：较宽的斜切、收分柱脚、厚墙与阴影窗洞，避免所有石块都鼓成肥皂。
- 金属：折边、卷边、法兰和壳体厚度；不把薄钢板整体做成实心厚砖。
- 布棚：受支撑点约束的弧线、轻微垂坠和可读的边沿；不靠随机噪声表现布料。
- 植物与积雪：重新组织大团块和曲线，保留叶间空隙、覆雪悬挑；不要只加叶片或雪粒数量。

保持用户已经认可的蓝天、纯色彩漆、紫墙与温室白骨架。材质细节不能再次把色彩冲淡。

### 5. 从共用原语进化到专属母版

建议共用四类生成能力：带洞墙段、截面放样壳体、连续曲面雨棚、嵌套面板。每张地图再保存自己的母版参数、色板、部件比例和2–3种受控组合。

例如同一放样工具可以生成船舱圆角前围和售货机外壳，但两者不共用同一套造型比例。保留可编辑 Blender 源件；对少量高出镜核心物件允许手工编辑母版，再由脚本摆放、合并、导出，不让“必须全自动造型”限制设计质量。

### 6. 灯光服务几何验收

先固定当前材质与光照，只改几何。新模型应该在同一机位下就能显出更好的外轮廓、结合阴影或体积转折。再做接触阴影与局部烘焙修整，最后微调材质。

不要同时换模型、升曝光、增加反射然后把所有改善归功于建模。烘焙补接触关系，实时光表现活动和模式变化。已有烘焙器会按区域细分长边，新几何必须同时统计烘焙前后面数，避免把造型优化的收益吃掉。

## 推荐实施顺序

**第一阶段：沙门一个街角样板。** 选择归档起点左侧可接近的商铺—窗—摊棚组合。它同时检验厚墙、真实深度、曲面棚和材料轮廓，且暖日光下容易看出几何本身的变化。仅重做这一组，不重生成全12图。保存当前同机位对照。

**第二阶段：货场一个工业样板。** 选出生点叉车和一组集装箱端门。它检验建筑式方案之外的机械壳体语言，避免把所有地图都改成相同的装饰建筑风格。

**第三阶段：办公室一组高频工位。** 用实际第一人称视角验证小尺度物件。文档历史记录中办公室 draw calls P50 为2629、帧间隔 P50 为15.60ms，不能视为还有充足性能空间；先清理重复内部面/材质，再分配新几何预算。

用户已授权分阶段推进全部地图。样板经实机对照和工程验证后，继续按对应类别扩展其他地图；过程中接受用户反馈调整。扩展的是已验证的建模方法，不是把同一个外形批量贴满12图。

## 验收方式与工程约束

1. 每个样板至少交付近景、正常战斗距离、侧向掠过视角。保持分辨率、机位、FOV、光照与曝光一致；静帧与短移动观察都要检查。
2. 第一眼应能指出主轮廓或空间深度变化。只有放大看螺丝/接缝才有差异的修改，不计作样板成功。
3. 先比几何版，再比重烘焙版。保留原色、天空与用户认可的光照重点；不以泛白提亮代替体积。
4. 保存布局/碰撞/导航数据差异检查，测试门洞、楼梯、掩体边缘射击、破坏和重开。新增视觉体块不得造成明显穿模、空气墙或错误射击预期。
5. 统计模型三角面、材质 surface 数、实际 draw calls、烘焙细分前后面数。每个螺栓不创建独立运行时节点；静态件按材质和空间区域合并。可破坏件、移动件仍保留独立生命周期。
6. 共用模型实例化仅用于确实重复的物件；不做横跨全地图的一大批次，避免破坏剔除。近景轮廓使用几何，远处按屏幕占比简化；高光敏感的重点边再考虑2–3段倒角，普通边继续低成本斜切。
7. 性能在同设备、同路线下分别测普通、狂暴切换、破坏状态，至少重复三次；采样中不截图，不并发跑 Blender 或其他游戏验证。P95/P99和超过预算的长帧数量都记录，不能只凭P50验收。

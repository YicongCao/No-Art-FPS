# Space：月球基地施工路线

日期：2026-11-14。分支：`space`，从 `e60721f` 创建。本文是现有策划案的实施顺序补充；已完成工具接入、基地混合资产试验，以及独立月球可玩样片的评审 A 版本。月球入口为 `scenes/moonbase.tscn`；原九图入口保留。当前证据见 [评审 A](review-a/index.html)。实测见 [基地试验报告](base-pilot/README.md)。

入口：[完整策划案](../../design/moonbase-plan-2026-11-13/index.html)、[构件五视图](../../design/moonbase-plan-2026-11-13/construction/index.html)、[构件数据](../../design/moonbase-plan-2026-11-13/construction/kit.json)。

## 已确定的边界

- 保留现有 60 秒玩法、两类敌人行为、命中与爆头逻辑、狂暴切换、移动和射击手感。更换视觉不顺带改数值。
- 基地只做室外：立面、封闭门、窗后暗板、平台与坡道；不增加可进入室内。
- 原有 43 类构件、12 组总装、16 个生成器家族是设计目录，不是必须一次写完的框架。五视图是尺寸化设计代理，不是已经完成的生产资产。
- 以当前 `project.godot` 的 `gl_compatibility` 和 Web 为实际目标。Box/Extrude/Lathe/Tube 是几何方法，落地使用 Blender Python、曲线、网格与修改器，不引入第二套 Three.js 游戏运行时。
- 分支内逐阶段提交并推送 `origin/space`；开发预览与主线线上版本分开。合并主线后的正式游戏更新才执行现有双站发布流程。

## 分阶段施工

### S0：工具与资产合同（本轮）

已安装官方 CLI/MCP 并验证只读工具；详情见 [接入记录](tripo-setup.md)。后续生成前记录模型版本、输入图/提示词、参数、种子（接口支持时）、任务 ID、花费和输出哈希。Tripo 种子不作为云端长期逐位复现承诺；保留实际下载结果。

生成物先进入本地原始区，整理后保存 `.blend` 到 `art_source/space/`，最终资产到 `assets/models/space/`，共享材质到 `assets/materials/space/`。这些是新目录约定，生产目录待实施时创建。采用米制、+Y 向上、约定正面 -Z；Blender 导出轴转换后在 Godot 用 1 m 标尺核对。底部或装配接口作为明确 pivot，socket、碰撞、LOD 和状态节点在 manifest 中注明。

### S1：灰盒、机位与材质基准

先按总平面搭 44×48 m 灰盒，保留飞船西侧路、工业站维修路、两处坡道。验证完整玩家胶囊、敌人移动、跳跃和主射线，不能以旧二维路线检测代替三维通行。

固定三个机位：概念图方向主视角、基地与工业站侧视角、近景箱体与敌人材质视角。锁定太阳方向、曝光与相机参数，建立暖白漆/橙漆/裸金属/深色机械/橡胶/月尘六块材质样板。

先用大形、适当倒角、法线和一盏主光做出面差，再加入环境反射及少量局部光。漆层 Metallic=0，露底金属才提高 Metallic；不要把白色表面提到过曝来“增强科幻感”。冷色补光服务可读性，不把阴影整片提成灰。

通过条件：原生与 Web 同机位截图；白壳能看出受光/背光，橙色保持饱和，8/15/20 m 的敌人轮廓可读。记录未加新资产时的帧时间基线。

### S2：两个程序化家族与 Tripo 样板比较

程序化先做 P01/P02 箱体三尺寸、I01/I02/I03 压力容器横竖两套。只实现实际需要的参数，不先建通用生成器编辑器。每个家族覆盖最小/典型/最大允许尺寸，检查倒角、UV、接口、法线、包络和碰撞。

Tripo 候选依次做箱体、飞船机头、机甲躯干；这是后续试点建议，本轮没有提交生成。输入使用去背景的单件设计图，不把整张 FPS 场景喂成一个模型，也不把带尺寸/文字的五视图图纸直接当多视图照片。多视图必须是同一个设计，背面需要与正面结构一致。

先查估价与可用参数，小批量逐件比较；关闭无必要的 8K/高清附加项，不把“重新生成一次”当免费修改。PBR 明确启用后检查实际输出是否含对应通道，不依赖预设名称。生成后先整理再判断，不以 Tripo 预览光照与 Godot 默认光照比较。

每件记录：生成花费、等待时间、Blender 清理时间、导出后三角形、材质槽、纹理驻留估算、固定机位截图、背面质量、修改一处结构所需时间。箱体优先评价变体效率；机头与躯干优先评价轮廓和清理成本。淘汰需要整体重做的初模，保留少量合格定稿。

### S3：完成一个可玩的高质量角落

组合基地门口的一段墙、坡道、栏杆，一组箱体和压力设备；加入一类敌人/武器样板，确认近看和战斗均成立。对应旧手册 K0/K1 与部分 K2，先形成效果标准再扩张。

制作共享 trim/atlas 和 PBR 配方。统一磨损/尘积蒙版驱动颜色、粗糙度、金属露底及适量法线；月面以月尘、擦伤、热变色为主，不默认雨痕、湿层或大片红锈。烘焙 AO 只表现局部遮蔽，不烘焙方向性太阳阴影进 Albedo；活动盖板不能留下永久黑影。

轮廓/大凹槽用几何，小倒角保留足够几何形成高光，细划痕用法线。螺钉近景共享网格，远处并入材质；避免“实例化每个螺钉”仍堆出大量场景节点。标识采用 UV/图集或小面积几何贴片，不依赖 Web 缺少的原生 Decal 功能。

通过条件：这一角落在 Web 有接近概念图的明暗与材料层次；完成命中、爆头、破坏、重开、狂暴完整回合。原始云模型之外必须有可编辑源与游戏导出物。

### S4：按冻结标准扩展全场与角色

按基地外壳、氧气站/横罐/发生器、飞船、围墙/天线/太阳能/岩石的顺序替换灰盒。G01–G16 只在真实资产需要时扩展；I10 散热器明确装进发生器/换热器总装，避免图册有构件但场景没有用途。

飞船先冻结机头、机翼、双尾翼三个主轮廓，再补发动机、落架、支架与挂载。机械总装的管路必须有起终点、法兰、端盖和支撑。每次替换重查净空，不允许模型附件侵占原来能通过的路线。

机甲的装甲和关节分工明确；静态躯干生成成功不代表已经有可用的骨骼动画。复用或适配当前动画和命中节点，检查头部命中、持枪姿势和两类敌人远距离辨识。枪械单独验收 ADS 对位、枪口、弹匣运动和第一人称屏幕占比。

地编按大地标、中尺度功能区、小道具逐层添加。重复物按空间块合并或 MultiMesh；可破坏盖板、受击对象及移动部件保持独立 ID。首版保留策划的 6–9 组互动，不将每个氧气罐都设为爆炸桶。

### S5：氛围与状态效果

P11 岩石小范围比较 Triplanar 与普通 UV；标识/装甲条用 UV。静态场景允许世界空间尘积，移动机甲用物体空间或 UV，避免走动时纹理游泳。完整 FBM/Voronoi/Domain Warp 在制作端烘焙；运行端只留下必要状态和低频混合。

先用局部无阴影灯提供真实落光，再用少量发光面和可关闭 Glow 补充灯环、枪口与瞄具。PBR 本身包含 Fresnel 响应，额外轮廓光必须通过 A/B，不能把所有边缘刷白。反射使用环境和少量一次更新探针，不承诺静态探针能反射移动敌人。

月球室外不用大面积空气雾；设备短时泄漏、局部受控尘粒可使用小范围粒子/透明几何。原生体积雾和 SSR 不进入 Compatibility 基线。Parallax 只作为少量近景实验，默认关闭；平面反射暂不实现。曝光和色调在 S1 就锁定，此处微调，不靠最后套滤镜掩盖材质问题。默认关闭色差、颗粒和强暗角，保证射击识别。

### S6：Web 验收与有针对性的优化

从 S1 起持续采集，S6 集中优化。加载阶段预载模型、材质和状态变体，狂暴时只切参数/复用对象，禁止临时构建几何、烘焙纹理或请求云模型。拆分 CPU/GPU/加载/着色器首用等原因后再优化，不根据包体小直接推断性能好。

固定设备、浏览器、渲染分辨率、敌人数和路线，比较冷启/暖启、普通战斗、狂暴前后、密集破坏、重开；记录 P50/P95/P99、最大长帧、绘制与可见三角形、透明覆盖、材质和纹理占用。手机必须在实际设备测，不以桌面触控模拟代替。

沿用主案初始预算：桌面暖机 P95≤16.7 ms、P99≤33.3 ms；代表机位约 200–300k 三角形、尽量≤300 draw calls；1 主阴影光、起点≤4 个重要局部无阴影灯；1–2 个静态探针；新增纹理 128–160 MiB、新地图压缩内容≤15 MB。它们是待验证目标，不是现阶段实测或跨设备承诺。

优先合并重复材质、按空间合理批处理、减少透明过绘与阴影、烘焙重复计算；之后再调整 LOD 和纹理。每次优化保留同机位前后图，避免以退灰、丢失高光或删除关键轮廓换帧数。

## 后续首个施工交付

S1 的灰盒与六种材质基准，加 S2 的一个程序化箱体、一套压力容器。Tripo 复杂初模试点紧接样板，不先批量生成全场。每个已完成阶段独立提交、推送；验收结论要区分结构检查、实际渲染、自动玩法检查和人工游玩。

- 已复核现有主案和构件手册，包括 K0–K5、共享蒙版、五视图与总装数据。本文 S0–S6 加入 Tripo 分工、前置光照样板及角色接入；不废弃原资产编号。

## 2026-11-14 基地试验后的调整

[实测报告与 Godot 对照图](base-pilot/README.md)表明：整体基地生成可快速建立造型，但近景栏杆、气闸和墙体精度不能直接通过。将 S2 增加“整体视觉基准 → 灰模/背面/材质槽审核 → 局部程序化替换”的支路；不先批量生成全场。下一项小验证是替换这栋的栏杆、坡道与门，测量实际清理工时。PBR 验收必须检查 AO/发光的实际连接，而非只确认文件名。原来的碰撞、尺寸、Web 和完整回合关卡继续保留。

## 2026-11-14 局部程序化替换实测

[栏杆、坡道与气闸替换报告](base-hybrid/README.md)：已完成独立构件、参数变体和同机位前后对照。结构可控性改善，但初版混合模型有 17 个网格、8 个材质，前视检查场景绘制调用从 9 增至 57。由此将后续输入流程改为“AI 主壳参考预留安装面，薄杆/坡道/门扇直接模块化装配”；不扩张逐栋切割完整 AI 楼的做法。近景采用混合结构，远景按需保留整体；材质融合与静态导出合批作为进入全场的关卡。

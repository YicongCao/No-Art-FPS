# 月球样片：概念差距复盘与后续施工计划

日期：2026-11-14。评估代码基线：`984a9d0`，分支 `space`。

结论：当前版本已建立可运行的月球射击场景，主要物件、敌人、交互和 UI 已接入；美术状态仍是“全场初版”，不是“概念图完成版”。下一步应停止扩充资产种类，集中解决构图、第一人称武器、月面与工业设施的视觉层次，同时开始已有性能问题的专项定位。

本轮仅检查与规划，不修改游戏。原有 A/B 通过记录仍有效；这里重新区分接入关卡与最终视觉验收，不把后续精修追溯成之前阶段失败。

## 3. 经验与教训

### 做对的部分

1. **混合制作路线适合这个项目。** 飞船、基地与机甲的复杂主壳可借助生成模型；栏杆、坡道、气闸、传感器、碰撞和交互件用程序化结构校准。生成器应服务明确构件，不追求先建一个无所不能的框架。
2. **运行时契约值得保留。** Head/Helmet、弹匣、手部与破坏目标等稳定节点，让换模型不必重写玩法；四红点能随头壳一起隐藏，就是这条路线的直接收益。
3. **固定机位、独立会话、实际 Web 导出有用。** 它们帮助发现持枪泛白、出生点被岩石占用、SVG 临时资源失效和旧资源混入等实际问题。
4. **保留源和原始数据降低返工成本。** 原始模型、程序化源、已批准阶段和逐帧记录让修改可追溯，不必重复付费生成，也不用依赖一次“更流畅”的主观印象。

### 需要纠正的部分

1. **把“接入完成”说成“补齐完成”。** 枪械已有模型、地球已有球体，但它们仍是需要完成的视觉资产。我上一轮对完成度的表达偏乐观。今后每项分开标记：已接入、视觉待评、视觉通过、性能待验；测试通过只对应测试覆盖的部分。
2. **先铺满全图，后发现视觉标准没定好。** 一个低完成度箱体复制二十次，得到的仍是低完成度场景。先把主视角的枪、一个设备单元、一块地表做成质量基准，再推广。
3. **噪声过早替代结构。** 当前表面生成器大范围使用相近尺度的噪声与划痕；它能增加表面信息，却不能修复导轨比例、平滑罐体、软山体和缺少承重逻辑的问题。先轮廓，再中尺度装配，再材质响应，最后微划痕。
4. **“同一组颜色”不等于统一画风。** 云资产已有密集细节，程序件较干净；拼在一起后细节密度不一致。需要按观看距离统一接缝宽度、倒角、粗糙度与纹理密度，而不是给所有物件贴同一层脏污。
5. **测试截图不自动成为美术验收证据。** D 的 `terrain.png` 机位主要被飞船遮住，不能证明山体与月壤完成；8/15/20 米截图也不能自动证明玩家辨识成功。每张图应标明要验证的对象，检查遮挡与屏幕尺寸；不合格机位要重取。
6. **用最高精度解决所有问题不划算。** 枪械长期占据近景，应获得更多建模资源；远景地球可以用可信底图和简单光照；四红点的识别效果也优于额外拟人脸部细节。预算应随屏幕重要性分配。
7. **性能延期不能变成不记录成本。** 材质细节提高后包体明显增长；单轮最大帧更低不能证明卡顿解决。继续保留指标，但现在应从“只记录”推进到可复现定位。

## 4. 性能基线及其限制

| 指标 | D 普通完整回合 | D 集中破坏回合 |
| --- | ---: | ---: |
| 原生 P50 帧间隔 | 5.436 ms | 5.242 ms |
| 原生 P95 | 7.876 ms | 7.659 ms |
| 原生 P99 | 8.969 ms | 8.795 ms |
| 原生最大帧间隔 | 38.285 ms | 38.772 ms |
| 43–48 秒区间最大帧间隔 | 12.352 ms | 24.116 ms |
| 绘制调用抽样范围 | 606–868 | 529–934 |

D 的 Chrome Web 单轮：P95 16.8 ms、P99 16.8 ms、最长 66.6 ms。当前四红点版 PCK 为 **75,290,472 字节，约 71.80 MiB**，791 个打包资源；资源数不是绘制调用数。D 之前 C 的 PCK 约 61.63 MiB。

原生为 Apple M5、1280×720、无 VSync/上限的单调时钟帧间隔；Web 为 Chrome RAF。两者不是 GPU 计时。压力回合额外集中破坏，不能与普通回合作等负载推断。性能数据来自 D；四红点版仅重跑功能和 Web 触控，**没有重新测性能**。物理手机尚未测，不能据此承诺手机 60 FPS。

## 5. 后续按六个关卡推进

以下为建议顺序和验收门槛，不代表已经实施，也不承诺未经实测的工时。

| 阶段 | 具体工作与边界 | 交付与放行标准 |
| --- | --- | --- |
| 0：冻结基线与验收口径 | 保留当前可玩版本。建立主视角、枪械近景、工业角落、无遮挡地形、阴影敌人五类机位；区分主观美术与自动功能结果 | 带坐标/FOV/分辨率/时间状态的截图清单；每项明确接入/视觉/性能状态。没有合格地形图就不能验收地形 |
| 1：性能定位与共性整理 | 固定种子、路径、敌人数；冷/暖启动各至少三次，拆开过载、破坏、叠加三种场景。先查 CPU/GPU、资源上传、首次状态使用。处理重复纹理、依赖、静态件等共性问题 | 同设备同画面前后数据，保留原始帧与长帧事件。减少帧时间或包体必须有证据；不通过降色彩、取消主阴影或减少交互目标冒充优化。即将重做的枪械拓扑不提前精调 |
| 2：近景枪械、HUD 与地球专项 | 枪械先做两种灰模比例方案，从持枪视角选型；完成侧置能量腔、机匣、护木、握把/手、紧凑瞄具。HUD 与枪械同屏对齐概念图的层级、轮廓、数字组合和边距。地球使用核验来源素材，完成明暗与云层 | 枪械灰模先评，再评材质；至少持枪、ADS、换弹、投掷四状态和横屏检查；HUD 另验 0/20 发、装填、999 击杀、亮暗背景与触控遮挡。地球须一眼可识别，不能仍是噪声球。保持弹量、枪口和瞄准规则 |
| 3：一张主视角的视觉定标 | 调整起点构图与装饰；完成一个氧气处理单元、一块地表/坑壁和基地外窗。统一白漆、金属、橡胶、玻璃的响应 | 同场景在主光、阴影、逆光和过载下可读；先灰模、后材质、再灯光。用户确认主视角后才能按这套密度扩展全图 |
| 4：模块推广与动作收敛 | 把已确认材质/构件推广至服务站、掩体、围墙；仅精修可接近飞船部位。调整机甲脚部接触、握枪与插槽，保留四红点 | 每一区域有无遮挡截图；无悬空、穿插、明显比例失衡。碰撞、导航、爆头、破坏、复位继续通过；增量开销写入台账 |
| 5：全回合与发布验收 | 再做最终资产的合批/LOD/资源裁剪，三局人工走查，耳机听感，目标手机温升与触控。满足后再安排主线整合及双站发布 | 真实设备、真实浏览器和人工结论分别记录；冻结资源哈希，保留回滚。space 预览不等于生产发布 |

建议的桌面 Web 暂定目标：同基准设备、1280×720、热运行固定脚本下，三轮 P95 不高于 18 ms、P99 不高于 25 ms；把可复现的过载/集中破坏事件帧控制在 33.3 ms 内。超过 50 ms 的帧逐项定位并记录，不承诺浏览器永不出现操作系统调度尖峰。加载冷启动单列。手机性能门槛待选定实际设备后制定，包体目标先按资源组成审计再设定，不拍一个缺少依据的数字。

## 6. 最小可执行下一批

建议下一次只执行阶段 0–1：修正证据机位，建立可复现长帧脚本和资源分解，完成一轮不牺牲画面的共性优化。与此同时产出枪械的轮廓约束与地球素材候选清单，不批量生产新资产。

随后将枪械与 HUD 作为同屏视觉交付、地球作为独立视觉交付，再完成“主视角样板”。这样用户能分别判断枪是否真正完成、地球是否可信、整个场景是否接近目标，而不是到全图替换后才发现同样的偏差。

现阶段不增加地图、敌人种类、玩法模式、基地室内、拟人脸部、水面或全场体积雾；不重新付费生成已接受的整艘飞船/整栋基地。任何新特效先回答它弥补哪一个可见缺口，再比较开销。

## HUD 补充纠正

用户指出 HUD 与概念图仍不同，这一项在初版计划中被低估。换字体、简化标签只完成了方向调整，不等于按概念图完成排版与图形。HUD 优先级调整为 P0，纳入阶段 2 的同屏验收。概念图未展示手雷库存和移动触控控件，不能据此删掉现有玩法需要的信息；应提供克制的扩展布局，并分别验收桌面与触控。概念图中的 24/120 是视觉参考，不作为修改弹量或新增有限储备弹药的授权。弹头轮廓使用 SVG 或矢量绘制，不使用 Unicode 字符替代图标。本次只修正规划，没有修改运行时 HUD。

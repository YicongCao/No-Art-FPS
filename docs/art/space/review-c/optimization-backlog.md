# 后续优化定位入口

本轮按要求先完成画面和交互，只记录开销，不把偶发长帧归因于尚未测量的子系统。灯光层修正前的 Web 回合曾观察到 250 ms 长帧，另见 `interim-long-frame-observation.json`；不要因最终一轮的最大值更低就判断问题已经消失。最终数字和逐帧时刻以本目录 `performance-issues.json` 及原始记录为准。

| 项目 | 已知事实 | 下一轮需要的证据 |
| --- | --- | --- |
| 开局及零散长帧 | Web 冷浏览器完整回合仍出现长帧；时间列表单独保存 | 主线程、首次材质/效果使用、上传与 GPU 时间的对应时间线，冷/暖启动重复测量 |
| 狂暴叠加破坏 | 压力回合于 44.4 秒击破全部目标、45 秒进入狂暴，已有独立 43–48 秒统计 | 相同随机种子、相同机位及敌人数重复测量，分别只切狂暴/只破坏/同时触发 |
| 围墙及重复装置 | 46 段围墙、17 盏灯具、3 组太阳能和 8 组交互物均为场景实例；尚未空间合批 | 绘制调用分解、主/阴影 pass、可见性；保留目标节点，静态重复件考虑空间分组 |
| 几何 | 连续山体 76,480 三角形；新道具详见制作源的 asset-stats.json | 近/远视角可见三角形、阴影距离、LOD 对轮廓的影响，固定机位前后图 |
| 包体与依赖 | PCK 仍包含共享旧角色/特效依赖；本轮未进行资源裁剪 | 按实际 PCK/导入资源统计重复纹理和几何，再决定移除与压缩，禁止仅按源文件大小推断 |
| 局部灯与持枪模型 | 场景无阴影局部灯增至 5；月球持枪模型使用专用层，场景补光只照场景层 | 每灯覆盖与材质 pass 开销；保留基准画面，不能靠泛白或去色减少成本 |
| 破坏效果 | 继续保留全局碎屑组上限，破坏目标只切显隐与命中碰撞；不动态建模/烘焙 | 批量破坏时的对象分配、峰值效果组和 CPU/GPU 时间；先测量再选择对象池或合批 |
| 手机 | 仅完成桌面 Chrome 触控模拟 | 真实目标手机、持续游玩温升、实际渲染分辨率与触控输入延迟 |

普通回合和集中破坏回合负载不同，不能因压力回合某个分位数更低就宣称破坏提升了性能。RAF 间隔也不能当作 GPU 帧时间。优化验证应保留颜色、材质响应、阴影、轮廓及可破坏目标数量的同机位对照。
